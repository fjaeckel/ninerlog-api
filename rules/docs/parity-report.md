ninerlog-api root; do not edit. The harness evaluates every golden case of every catalogue rule
that maps to an API code rule (`inventory/code-rules.yaml` `maps_to`) or names a divergence,
with the engine and with the API's own as-of evaluation (`currency.Service.EvaluateAsOf`,
training templates, the readiness medical check) on the same record, and compares subject,
status, message key and, per requirement name key, current, required and met. Every difference
must be explained by a divergence the rule files declare (`<rule>#<id>`, one CHANGELOG line
each), by an input gap the API cannot hold, or by a presentation note; the table is
`internal/service/currency/rulesparity/testdata/expectations.yaml`. The test fails on an
unexplained difference, on a stale expectation, and on a declared divergence that no case
demonstrates unless it is marked not observable with a reason.

## Not compared

- Remedy keys and params, message params, `validUntil`, `expiresOn`, `windowOpensAt` and
  `lastDate`.
- Requirement rows only one side reports: counted above, never a failure.
- Which training programmes the API lists: it selects them from the pilot profile's
  disciplines, which a record does not carry; the harness evaluates the programmes the engine
  evaluates.
- Readiness medical items the engine does not evaluate (readiness lists every medical, the
  catalogue only those of the licences' authorities); readiness has no expiring state, so an
  engine `expiring` medical compares as valid.
- Flights dated after `asOf`: the API's reads have no upper date bound, so the harness gives
  the API only the flights up to `asOf`, as an as-of evaluation assumes no later flying.

## Record to API mapping

Record flights become `models.Flight` rows on synthetic fleet aircraft (one per class,
ultralight kind, MTOM and registration); `launches: 0` is a NULL launches column; distances
are converted to nautical miles. Events of kind `proficiency_check`, `flight_review` and `ipc`
become flag-only rows seen only by the check and review reads; other events, `holder`,
`variants`, licence kinds, type designators, `validFrom` and the optional flight fields have no
API column and are dropped. A rating class the API has no value for is entered as OTHER; a
privilege kind it has no value for is dropped. A passenger result is compared with the
compared catalogue rules on the same subject and part (day or night) combined: the worst
status with its message, and all their rows.
